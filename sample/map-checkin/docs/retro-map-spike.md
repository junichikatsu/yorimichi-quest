# 地図のドット絵調表示（spike）

> 検討中の試作です。既定の表示には影響しません。本採用するかは実物を見てから決めます。
> 関連: [issue #11](https://github.com/junichikatsu/yorimichi-quest/issues/11)

## 使い方

URL に `?retro=1` を付ける。

```
http://localhost:8787/?retro=1
```

見た目の好みは実物を見ないと決められないので、2 つだけ URL で振れるようにしてある。

| パラメータ | 既定 | 内容 |
| :--- | :--- | :--- |
| `retroWidth` | `256` | キャンバスの横幅（px）。小さいほどドットが大きい。64〜1024 |
| `retroLabels` | 無効 | `1` を付けると地名・道路名のラベルを残す |

```
?retro=1&retroWidth=160        もっと粗く
?retro=1&retroWidth=384        もっと細かく
?retro=1&retroLabels=1         ラベルを残す
```

Mapbox のアクセストークンが未設定だと地図自体が出ない（一覧表示になる）ので、このフラグも効かない。

## 3 段構え

「ドット絵調」はひとつの処理では作れない。**どれか 1 つでも欠けるとモザイクに見える。**

| | 何を | どこで |
| :--- | :--- | :--- |
| 1 | 解像度を落とす | `retro/index.ts`（`window.devicePixelRatio` の差し替え） |
| 2 | 情報量を落とす | `retro/simplify.ts`（細い道・縁取り・ラベルを間引き、道路を太らせる） |
| 3 | 合成後の色をパレットへ丸める | `retro/quantize.ts` + `retro/renderer.ts` |

### なぜ 3 が要るのか

**最初の版は 1 と 2 のうち 1 しか無く、「モザイクをかけただけ」に見えた。** 原因は色にある。

Mapbox の color-theme（LUT）は**レイヤーを描く時点**で効く。レイヤー同士を重ねるときの半透明合成や、
線のアンチエイリアスで生まれた中間色はそのまま残る。さらに解像度を落とすと、
その中間色が「隣り合う 2 色を混ぜた大きな正方形」として並ぶ。これはまさにモザイクの作り方そのもの。

ドット絵は逆で、**1 ドットが必ずパレットのどれか 1 色**になっていて、色の境界が 1 ドットで切り替わる。
そこで、地図と霧を合成し終えた画に対してもう一度パレットへ丸めている。

合成順にも意味がある。霧は**丸める前に**重ねる。あとから半透明で重ねると、
せっかく丸めた色の上に中間色が乗ってしまう。

### 1. 解像度

Mapbox GL JS はキャンバスの大きさをこう決めている（`mapbox-gl-dev.js:107796`）。

```js
_resizeCanvas(width, height) {
  const pixelRatio = exported.devicePixelRatio || 1;
  this._canvas.width  = pixelRatio * Math.ceil(width);   // バッキングストア
  this._canvas.height = pixelRatio * Math.ceil(height);
  this._canvas.style.width  = `${width}px`;              // 表示上の大きさ
  ...
}
```

`exported.devicePixelRatio` は `window.devicePixelRatio` を毎回読む getter（`:9155`）で、
内部に保持していない。差し替えると、**表示上の大きさはそのままでバッキングストアだけが粗くなる**。

比率はコンテナ幅から毎回計算していて、キャンバス幅が `retroWidth`（既定 256px）へ寄る。
画面が大きいほどドットも大きくなるので、見た目の粗さは端末によらずだいたい揃う。

霧のキャンバスも同じ `window.devicePixelRatio` を読んでいるため、自動的に同じ粗さに揃う。

### 2. 情報量

ドット絵に見えない原因の半分は解像度ではなく**描かれている量**にある。
streets-v12 は細い道・縁取り・POI アイコン・ラベルを大量に持っていて、
横 256px まで落とすとそれらが 1 ドット未満の粒になり、ただのノイズになる。
ファミコンの地図画面が読めるのは、最初から大きく単純な形だけで描かれているから。

本来はカスタムスタイルを書き起こすべきところだが、spike なので読み込み済みのスタイルから機械的に間引いている。
判定はレイヤーの種類と id の規則だけで、個別のレイヤー名には依存しない。

- `fill-extrusion` / `hillshade` / `heatmap` / `sky` を消す
- `symbol`（ラベル）を消す（`retroLabels=1` で残せる）
- id が `-case` で終わるレイヤー（道路の縁取り）を消す
- id が `road` で始まる線を 2.5 倍に太らせる

ラベルを既定で消しているのは、Mapbox 配信の SDF フォントで描かれるため粗くするとほぼ読めないから。
ドットフォントに差し替えるところまでやれば戻せる（範囲外）。

### 3. 色

- 出来上がった画の全画素を、ファミコンのパレット 55 色のうちもっとも近い色へ丸める
- 「上位 5bit の RGB → パレットの色」の対応表（32768 通り）を起動時に 1 回だけ作る
- color-theme の LUT も同じ対応表から作るので、両者で色がずれない

LUT のほうは今や必須ではない（最後に丸めるので）が、
広い塗りの色が最初から正確にパレットへ乗るぶん、境界に出る中間色が減るので残している。

## ファイル

```
apps/web/src/retro/
  index.ts        フラグと URL パラメータ、devicePixelRatio の差し替え
  simplify.ts     スタイルの間引き
  quantize.ts     パレットへの丸め（対応表）
  renderer.ts     地図 + 霧の合成 → 丸め → 表示
  lut.ts          cube strip LUT の生成
  nes-palette.ts  ファミコンのパレットと最近傍探索
  retro.test.ts   DOM を使わない部分のテスト
```

呼び出しは `apps/web/src/components/MapView.tsx`、CSS は `apps/web/public/styles.css` の `.map--retro` / `.map__retro`。

## 検証済みのこと

ヘッドレス Chrome で確認した（Mapbox のトークンが不要な範囲）。

**色の丸め** — 地図に見立てた画（なめらかな階調＋細い斜線＋半透明の霧）を通した結果:

| | 処理前 | 処理後 |
| :--- | ---: | ---: |
| 出てくる色の数 | 2,693 | 12 |
| うちパレット外の画素 | 全部 | 0 |

**性能** — 256×200 の合成 + 丸めが 1 フレーム **0.43ms**（60 回の平均）。

**その他**

- LUT は 1024×32 の PNG で、Mapbox の要件（高さ ≤ 32 / 幅 = 高さ²）を満たす。生成 32ms、一度だけ
- `retroWidth=256` / `=160` がそれぞれキャンバス幅 256px / 160px になる
- 後始末で `devicePixelRatio` が元へ戻る

## 未検証・確認したいこと

**実機と Mapbox のトークンが要るもの。上の検証は合成画像に対するもので、実際の地図は見ていない。**

- `streets-v12` で `setColorTheme` が効くか（ドキュメントは Mapbox Standard 前提の記述）
- 間引きの加減が妥当か。消しすぎ／残しすぎていないか
- `retroWidth` の落としどころ。既定の 256 が粗すぎ／細かすぎないか
- 道路を 2.5 倍に太らせた結果が破綻していないか（`line-width` が式のレイヤーを機械的に包んでいる）
- スマートフォンでの描画性能。`preserveDrawingBuffer` を有効にしているぶんの影響
- 歩きながら見て酔わないか

## 既知の限界

- **マーカー・コントロール・帰属表示は DOM なので粗くならない。** 角丸と影を落として硬い見た目に寄せてあるが、
  ドット絵そのものではない。スプライト化は範囲外
- **ラベルが出ない**（既定）。ドットフォントへの差し替えは範囲外
- **`window.devicePixelRatio` の差し替えは Mapbox の公開 API ではない。** 実装が変われば効かなくなる。
  `retro/index.ts` の中だけで完結させ、後始末で元に戻している
- **`preserveDrawingBuffer: true` が要る。** 毎フレーム地図キャンバスを読むため。
  ドライバ側の最適化が効かなくなるぶんの負荷がある

## Mapbox の利用条件

**ロゴの加工は禁止、帰属表示は可読でなければならない**（[Attribution requirements](https://docs.mapbox.com/help/getting-started/attribution/)）。

このため `.map__gl` のコンテナごと拡大縮小する実装は採れない。
ロゴ・帰属表示・ナビゲーションコントロールはキャンバスの兄弟要素なので、
**キャンバスだけを粗くする**現在の方式ならこの条件を満たす。
