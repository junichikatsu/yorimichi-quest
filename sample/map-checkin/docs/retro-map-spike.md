# 地図のドット絵調表示（spike）

> 検討中の試作です。既定の表示には影響しません。本採用するかは実物を見てから決めます。
> 関連: [issue #11](https://github.com/junichikatsu/yorimichi-quest/issues/11)

## 使い方

URL に `?retro=1` を付ける。

```
http://localhost:8787/?retro=1
```

| パラメータ | 既定 | 内容 |
| :--- | :--- | :--- |
| `retroWidth` | `256` | 横に並ぶドットの数。小さいほど粗い。64〜1024 |
| `retroLabels` | 表示 | `0` を付けると地名・施設名を消す |

```
?retro=1&retroWidth=160        もっと粗く
?retro=1&retroWidth=384        もっと細かく
?retro=1&retroLabels=0         文字なし
```

Mapbox のアクセストークンが未設定だと地図自体が出ない（一覧表示になる）ので、このフラグも効かない。

## 作り

**地図は通常の解像度のまま描かせ、後処理で縮小する。**

```
地図キャンバス（素の解像度）
      ＋                → 横 256 ドットへ縮小 → パレット 55 色へ丸め → 拡大表示
霧キャンバス（素の解像度）
```

文字とピンはこの後処理を**通さない**。別レイヤーとして素の解像度のまま上に重ねる。

### 重ね順

見え方はほぼこれで決まる。`.map` の子はすべて絶対配置なので、`z-index` で明示的に積んでいる。

| | 要素 | 中身 |
| ---: | :--- | :--- |
| 2 | `.map__gl` | スポットのピン、ナビゲーション、Mapbox のロゴと帰属表示（地図キャンバスは `opacity: 0`） |
| 1 | `.map__labels` | 地名・施設名（素の解像度） |
| 0 | `.map__retro` | ドット絵にした地図 |

DOM の並び順のままだと `.map__retro` が `.map__gl` のあとに来るため、**ピンやコントロールを覆い隠してしまう**。

### 色

出来上がった画の全画素を、ファミコンのパレット 55 色のうちもっとも近い色へ丸める。
「上位 5bit の RGB → パレットの色」の対応表（32768 通り）を起動時に 1 回だけ作って使い回す。

これが要。Mapbox の color-theme（LUT）は**レイヤーを描く時点**で効くので、
レイヤー同士の半透明合成や線のアンチエイリアスで生まれた中間色はそのまま残る。
そこへ解像度を落とすと、中間色が「隣り合う 2 色を混ぜた大きな正方形」として並ぶ ——
これはモザイクの作り方そのもの。ドット絵は逆に、1 ドットが必ずパレットのどれか 1 色になる。

合成順にも意味がある。霧は**丸める前に**重ねる。あとから半透明で重ねると、
せっかく丸めた色の上に中間色が乗ってしまう。

color-theme の LUT も併用しているが、最後に丸めるので必須ではない。
広い塗りが最初から正確にパレットへ乗るぶん、境界に出る中間色が減るので残している。

### 情報量

streets-v12 は細い道・縁取り・POI アイコンを大量に持っていて、横 256 ドットでは
1 ドット未満の粒＝ノイズになる。ファミコンの地図画面が読めるのは、
最初から大きく単純な形だけで描かれているから。

本来はカスタムスタイルを書き起こすところだが、spike なので読み込み済みのスタイルから機械的に間引く。
判定はレイヤーの種類と id の規則だけで、個別のレイヤー名には依存しない。

- `symbol` / `fill-extrusion` / `hillshade` / `heatmap` / `sky` を消す
- id が `-case` で終わるレイヤー（道路の縁取り）を消す
- id が `road` で始まる線を 2.5 倍に太らせ、**1.5 ドットを下限にする**

下限があるのは、ズームアウトすると道路が 1 ドットより細くなり、縮小の平均に溶けて消えるため。

### 文字

ドット絵の後処理は地図キャンバスを丸ごと縮小するので、文字も一緒に潰れて読めなくなる。
かといって文字だけ後処理から外すことは、1 枚のキャンバスに描かれている以上できない。

そこで**ラベル専用の地図をもう 1 枚**作り、背景と塗り・線をすべて消して文字だけを描かせ、
位置を本体へ追従させている（`jumpTo` なので遅れない）。操作は受けず、当たり判定も持たない。

代償として Mapbox の地図インスタンスが 2 つになり、同じベクタタイルを 2 回取りに行く。
本採用するなら「ドットフォントを用意して 1 枚に戻す」か「文字だけ自前で描く」を検討すること。

## 以前の版からの変更

| | 以前 | 今 |
| :--- | :--- | :--- |
| 粗くする方法 | `window.devicePixelRatio` を差し替えて Mapbox に粗く描かせる | 素の解像度で描かせ、後処理で縮小 |
| 文字 | 既定で非表示（残すと読めない） | 素の解像度で上に重ねる |
| ピン | **retro キャンバスに隠れて見えなかった** | `z-index` で最前面 |
| 細い道 | 描画時に消える | 縮小の平均に色として残る |
| 非公式な手 | `devicePixelRatio` の差し替え | なし |

`devicePixelRatio` の差し替えをやめたのは、それだとラベルも一緒に潰れて救えないため。
結果として非公式なやり方が 1 つ減り、細い道が消える問題も和らいだ。

## ファイル

```
apps/web/src/retro/
  index.ts        フラグと URL パラメータ
  renderer.ts     地図 + 霧の縮小合成 → 丸め → 表示
  quantize.ts     パレットへの丸め（対応表）
  labels.ts       ラベル専用の地図
  simplify.ts     スタイルの間引き
  lut.ts          cube strip LUT の生成
  nes-palette.ts  ファミコンのパレットと最近傍探索
  retro.test.ts   DOM を使わない部分のテスト
```

呼び出しは `apps/web/src/components/MapView.tsx`、CSS は `apps/web/public/styles.css` の `.map--retro` / `.map__retro` / `.map__labels`。

## 検証済みのこと

ヘッドレス Chrome で確認した（Mapbox のトークンが不要な範囲）。
地図に見立てた 1600×1200 の画（なめらかな階調＋1px の細い斜線 40 本＋半透明の霧）を通した結果:

| | 色の数 | パレット外の画素 | 1 フレーム |
| :--- | ---: | ---: | ---: |
| 処理前 | 5,787 | 1,920,000（全部） | — |
| `retroWidth=160` | 9 | **0** | 0.43ms |
| `retroWidth=256`（既定） | 11 | **0** | 1.07ms |
| `retroWidth=384` | 12 | **0** | 2.06ms |

そのほか

- LUT は 1024×32 の PNG で、Mapbox の要件（高さ ≤ 32 / 幅 = 高さ²）を満たす。生成 16ms、一度だけ
- URL パラメータが既定値・指定値ともに意図どおり読める

## 未検証・確認したいこと

**実機と Mapbox のトークンが要るもの。上の検証は合成画像に対するもので、実際の地図は見ていない。**

- `streets-v12` で `setColorTheme` が効くか（ドキュメントは Mapbox Standard 前提の記述）
- ラベル専用の地図が本体とずれずに追従するか。文字の量が多すぎないか
- ズームアウトしたときに読めるか。道路の下限 1.5 ドットで足りているか
- `retroWidth` の落としどころ
- スマートフォンでの描画性能と通信量。地図インスタンスが 2 つ、`preserveDrawingBuffer` も有効

## 既知の限界

- **Mapbox の地図インスタンスが 2 つ**になり、同じベクタタイルを 2 回取りに行く
- **`preserveDrawingBuffer: true` が要る。** 毎フレーム地図キャンバスを読むため。
  ドライバ側の最適化が効かなくなるぶんの負荷がある
- **文字は素のまま**で、ドットフォントではない。地図だけがドット絵になる
- **アンチエイリアスの完全な排除はしていない。** 縮小時に平均してから丸めているので、
  境界には「どちらでもない色」がパレット内の色として 1 ドット出ることがある。
  細い道が消えないのはこのおかげでもあるので、意図的にこうしている

## Mapbox の利用条件

**ロゴの加工は禁止、帰属表示は可読でなければならない**（[Attribution requirements](https://docs.mapbox.com/help/getting-started/attribution/)）。

ロゴと帰属表示は `.map__gl` の中にあり、最前面に鮮明なまま残る。
ラベル専用の地図が出す 2 つめのロゴ・帰属表示は CSS で隠しているが、これは加工ではなく重複の除去で、
表示義務は本体側の 1 つで満たしている。
