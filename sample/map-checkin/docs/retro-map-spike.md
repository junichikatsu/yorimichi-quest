# 地図のドット絵調表示（spike）

> 検討中の試作です。既定の表示には影響しません。本採用するかは実物を見てから決めます。
> 関連: [issue #11](https://github.com/junichikatsu/yorimichi-quest/issues/11)

## 使い方

URL に `?retro=1` を付ける。

```
http://localhost:8787/?retro=1
```

| パラメータ | 既定 | 内容 |
| :--- | :--- | :--- |
| `retroWidth` | `256` | 横に並ぶドットの数。小さいほど粗い。64〜1024 |
| `retroLabels` | 表示 | `0` を付けると地名・施設名を消す |
| `retroFog` | `shade` | 未踏エリアの見せ方。`dither` で市松模様に戻す |

```
?retro=1&retroWidth=160        もっと粗く
?retro=1&retroWidth=384        もっと細かく
?retro=1&retroLabels=0         文字なし
```

Mapbox のアクセストークンが未設定だと地図自体が出ない（一覧表示になる）ので、このフラグも効かない。

## 作り

**地図は通常の解像度のまま描かせる。ドット絵にするのは未到達エリアだけ。**

```
素の地図（そのままの解像度）
      ↑ 未到達エリアだけ、横 256 ドットへ縮小してパレットへ丸めた層を
        最近傍で拡大して重ねる
```

到達エリアはドット層を透明にするので、下の地図がそのまま見える。
**粗さの違いがそのまま境目になる**ので、色だけで分けるより境目がはっきりする。
歩くほど世界の解像度が上がっていく、という見え方になる。

マスクはドット解像度で 2 値化してから拡大するため、境目もドット単位で階段状になる。

文字とピンはこの処理を**通さない**。別レイヤーとして素の解像度のまま上に重ねる。

### 重ね順

見え方はほぼこれで決まる。`.map` の子はすべて絶対配置なので、`z-index` で明示的に積んでいる。

| | 要素 | 中身 |
| ---: | :--- | :--- |
| 2 | `.map__gl` | スポットのピン、ナビゲーション、Mapbox のロゴと帰属表示（地図キャンバスは `opacity: 0`） |
| 1 | `.map__labels` | 地名・施設名（素の解像度） |
| 0 | `.map__retro` | ドット絵にした地図 |

DOM の並び順のままだと `.map__retro` が `.map__gl` のあとに来るため、ピンやコントロールを覆い隠してしまう。

### 色は「近い色を探す」のではなく「決め打つ」

元のスタイルの色を機械的にパレットへ丸めると、灰色と青緑ばかりの潰れた地図になる。
現実の地図向けの配色は明度も彩度も近い色が多く、丸めると差が消えるため。

そこで**地物ごとに色を決め打つ**（`retro/palette.ts`）。選んでいるのはすべてファミコンのパレットにある色で、
最後の丸めでも変化しない。

| 地物 | 色 |
| :--- | :--- |
| 地面 | `#fce0a8` 砂色 |
| 緑地 | `#00a800` 緑 |
| 水面 | `#0058f8` 青 |
| 幹線道路 | `#f8b800` 琥珀 |
| 生活道路 | `#fcfcfc` 白 |
| 建物 | `#ac7c00` 金茶 |

`landuse` は公園だけでなく住宅地・商業地・病院も抱えているので、`class` で振り分ける。
一律に緑へ塗ると都心が森になる。

### 未到達エリアは「暗いパレット」＋ドット絵

半透明で重ねるのは駄目だった。全部の色が濁り、地面の砂色が灰色に、水の青が紫に転んで、
地物ごとに色を決めた意味が消える。

次に市松模様を試した。実機に半透明は無く、これで薄く見せていたからで、色は濁らない。
ただし**画面いっぱいに 1 ドット周期の模様が出ると目がちらつく**。
拡大時のドット格子と干渉して細かく明滅するためで、探索率 0% では画面全体がこれになる。

最終的にファミコンのもう 1 つの常套手段、**パレットの差し替え**を使っている。
同じ絵を暗い色の組で描いて夜や影を表す手で、模様が出ないのでちらつかず、色みが残るので
未踏エリアでも地図として読める。

| 探索済み | 未踏 | |
| :--- | :--- | :--- |
| `#fce0a8` 砂 | `#ac7c00` 金茶 | 地面 |
| `#fcfcfc` 白 | `#f8d878` 淡い金 | 生活道路 |
| `#f8b800` 琥珀 | `#503000` 焦茶 | 幹線道路 |
| `#00a800` 緑 | `#006800` 深緑 | 緑地 |
| `#3cbcfc` 空色 | `#0058f8` 青 | 水面 |

対応は「元の色を 0.65 倍していちばん近いパレット色」を機械的に選ぶ。
色みが失われる 4 つ（地面・道路 2 種・水面）だけ手で指定している。

市松模様は `?retroFog=dither` で戻せる。比べられるように残してある。

暗いパレットは**ドット絵かどうかの違いと重ねて**効かせている。
未到達は「粗い＋暗い」、到達は「素の解像度＋明るい」で、2 つの手がかりが同時に切り替わる。

### 道路の太さはズームに依らない固定値

元のスタイルは `line-width` をズームの式で持っている。ズームアウトすると 1 ドットより細くなり、
縮小の平均に溶けて消える。「ズームアウトすると分かりづらい」の主因がこれ。

幹線 4 ドット / 主要 3 / 補助 2 / 生活道路 1.5 に固定する。どのズームでも同じ太さで残る。

なお元の式に倍率を掛ける形（`[*, 元の式, 2.5]`）は**使えない**。
Mapbox は zoom 式が `step` / `interpolate` の最上位にあることを要求するため、掛け算で包むと式ごと拒否される。

### スタイルの fog を消す

streets-v12 は `fog.color` に**白**を持っていて、Mapbox v3 はこれを全画面に描く。
ラベル専用の地図では塗りを全部隠しているので、消さないと真っ白な面だけが残り、下のドット絵が見えなくなる。
本体側でも色が薄まるので消している。

### 文字

ラベル専用の地図をもう 1 枚作り、塗りと線をすべて消して文字だけを描かせ、位置を本体へ追従させる。

- 日本語名（`name_ja`）があれば優先する。既定は英語表記
- 白で太く縁を取る。ドット絵の地図は模様が細かく、既定の細い縁では文字が沈む
- 標識・矢印・POI アイコンは出さない。名前だけでよい

代償として Mapbox の地図インスタンスが 2 つになり、同じベクタタイルを 2 回取りに行く。
本採用するなら「ドットフォントを用意して 1 枚に戻す」か「文字だけ自前で描く」を検討すること。

## ファイル

```
apps/web/src/retro/
  index.ts        フラグと URL パラメータ
  palette.ts      地物ごとの色と、未踏エリアの暗いパレット
  simplify.ts     スタイルの塗り替えと間引き
  renderer.ts     地図 + 霧の縮小合成 → 丸め → 表示
  quantize.ts     パレットへの丸め（明暗 2 組の対応表）
  labels.ts       ラベル専用の地図
  nes-palette.ts  ファミコンのパレットと最近傍探索
  retro.test.ts   DOM を使わない部分のテスト
```

呼び出しは `apps/web/src/components/MapView.tsx`、CSS は `apps/web/public/styles.css` の
`.map--retro` / `.map__retro` / `.map__labels`。

## 実機で見て直したこと

Mapbox のトークンを借りて実際に描かせたところ、机上では分からなかった不具合が並んで出た。

| 症状 | 原因 |
| :--- | :--- |
| 地名が 1 つも出ない | `.map--retro .mapboxgl-canvas { opacity: 0 }` の範囲が広すぎ、ラベル用地図のキャンバスまで透明にしていた |
| 地名が出ても地図が真っ白 | streets-v12 の `fog.color` が白。塗りを全部隠すと、この白い面だけが残る |
| 道路が細いまま | `['*', 元の式, 2.5]` は Mapbox に拒否される（zoom 式は最上位である必要がある）。**全レイヤーで失敗していた** |
| 灰色と青緑ばかりの地図 | 元の色を機械的に丸めていた。加えて霧を半透明で重ねて全部の色を濁らせていた |
| 都心が一面の森 | `landuse` を一律に緑で塗っていた |
| スポットのピンが見えない | ドット絵のキャンバスが DOM の並び順で後に来るため、ピンとコントロールを覆い隠していた |
| 目がちかちかする | 市松模様を 1 ドット周期で敷いていた。拡大時のドット格子と干渉して細かく明滅する |

## 確認したこと

ヘッドレス Chrome を CDP で駆動し、実時間を待ってから撮影して確認した。
`--virtual-time-budget` では Mapbox のタイル読み込みが間に合わない。

- 1000×700 と 390×844（スマートフォン相当、dpr 2）の両方で、地図・地名・ピンが揃って出る
- ズームアウト（z14 → z12）でも道路の太さが変わらず、地物が読める
- デモ用の導線で軌跡を記録すると、探索済みの帯だけ明るいパレットに変わる
- 画面に出る色は 5 色で 94% を占める（地面 33% / 生活道路 29% / 緑地 17% / 幹線 11% / 水面 5%）
- 合成 + 丸めは 1 フレーム 1ms 前後（`retroWidth=256`、1000×700）

## 残っている課題

- **地図インスタンスが 2 つ。** 文字を素の解像度で出すためにラベル専用の地図を重ねており、
  同じベクタタイルを 2 回取りに行く。本採用するならドットフォントで 1 枚に戻したい
- **文字は素のフォント**で、ドット絵ではない。日本語は `localIdeographFontFamily` で
  ローカルフォントに差し替えられるので、ドットフォントを用意すればここは解決できる
- **ドットの大きさが画面幅で変わる。** 横 256 ドット固定なので、画面が狭いほど 1 ドットが小さい。
  スマートフォンでは `?retroWidth=160` あたりが見やすい
- **建物が出ない。** streets-v12 は z15 以上でないと建物を描かない。色は用意してある
- **合成が素の解像度になった。** 到達エリアを鮮明に見せるため、1 フレームにつき
  素の解像度の drawImage が 2 回入る。ヘッドレス（SwiftShader / ソフトウェア描画）で 13〜20ms。
  実機の GPU ではもっと速いはずだが、**スマートフォンでの実測が要る**。
  重いようなら、ドット層を CSS の重ね順で地図の上に置いて合成をやめる手がある
  （素の解像度の drawImage が 0 回になる。ただし重ね順の制御が繊細になる）
- **`preserveDrawingBuffer: true` が要る。** 毎フレーム地図キャンバスを読むため

## Mapbox の利用条件

**ロゴの加工は禁止、帰属表示は可読でなければならない**（[Attribution requirements](https://docs.mapbox.com/help/getting-started/attribution/)）。

ロゴと帰属表示は `.map__gl` の中にあり、最前面に鮮明なまま残る。
ラベル専用の地図が出す 2 つめのロゴ・帰属表示は CSS で隠しているが、これは加工ではなく重複の除去で、
表示義務は本体側の 1 つで満たしている。
