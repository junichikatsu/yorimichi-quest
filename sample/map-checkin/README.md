# サンプル: map-checkin（地図＋チェックイン）

要件定義書（[../../doc/requirements.md](../../doc/requirements.md)）の**平時モードのコア体験**を、
動く形で確認するためのサンプル実装です。**正式な開発ではありません。**
他のサンプルとは独立したワークスペースです（[サンプル一覧](../README.md)）。

- 地図: **Mapbox GL JS**
- 言語: **TypeScript**
- フロントエンド: **React**（esbuild で iife にバンドル）
- 実行環境 / 配信 / DB: **enebular**（クラウド実行環境 ZIP + データストア）

対応する要件: FR-02（マップ・スポット表示）／FR-03（チェックイン）／FR-07（ポイント）／
FR-10（オープンデータ取込＝シード）／FR-11（計測の素地）。
写真投稿・AI 解析・クイズ・相互検証・有事モード・行政ダッシュボードは**対象外**です。

歩いたところが地図に残る**フォグ・オブ・ウォー**（未踏エリアを霧で覆い、通った道だけ晴れる）を
併せて実装しています。要件定義書には無い追加要素で、「寄り道して街を開拓する」体験の確認用です。

## クイックスタート（ローカル）

```bash
cd sample/map-checkin
pnpm install

# 別ターミナル: フロントエンドの監視ビルド
pnpm dev:web

# APIサーバー（ローカルはインメモリのデータストアを使う）
pnpm dev
# → http://localhost:8787/
```

Mapbox のトークンが無くても起動します（地図の代わりに一覧表示になります）。
地図を出すには `sample/map-checkin/.env` を作って `MAPBOX_ACCESS_TOKEN` を設定してください（`.env.example` 参照）。

現地に行かずにチェックインを試す場合は、スポットを選んで
「デモ用：現在地をこの場所に設定する」を押してください。
霧が晴れる様子を見るには「デモ用：ここまで歩いた軌跡を記録する」を押すと、
現在地から選んだスポットまでの経路がまとめて塗られます。

## コマンド

| コマンド | 内容 |
| :--- | :--- |
| `pnpm dev` | API サーバーをローカル起動（fake データストア） |
| `pnpm dev:web` | フロントエンドの監視ビルド |
| `pnpm typecheck` | 全パッケージの型チェック |
| `pnpm lint` | ESLint（`apps/web` では `innerHTML` を禁止） |
| `pnpm test` | Vitest（core / datastore / function の統合テスト） |
| `pnpm build:zip` | デプロイ用 ZIP を生成（web ビルド → バンドル → handler 検証 → ZIP） |
| `pnpm verify` | typecheck → lint → test → ZIP ビルドを通しで実行 |

## ゲーム要素（Issue #25）

`sample/battle-prototype` で検証した要素のうち、**キャラメイク・キャラクターの表示・アイテム収集・クイズ**を移植しています（戦闘要素は対象外）。

| 要素 | 動き |
| :--- | :--- |
| キャラメイク | 髪型10種・服10種・髪／服／肌の色・名前を選ぶ。結果はデータストアに保存される |
| キャラクターの表示 | 地図上の現在地にドット絵で立つ。**装備しているアイテムが見た目に反映される** |
| **カード収集（FR-14）** | 行動・道具・場所・ミッションの4種を**カード**として集める。状態は**達成／未達成（仮に所持）**の2つだけ |
| クイズ | チェックイン後に出題。**不正解でもポイントは減らず、必ず解説を出して何度でも挑戦できる** |

**出題は「まず何をするか」を優先します**（設計原則 G-8）。防災士講座で「発災直後はまず身を守る、
生き残るのが先。死んだらため込んだグッズは使えない」と示された指摘を受けたもので、
備蓄や設備を問う設問しか出ないと「モノをそろえれば備えたことになる」という逆の学習になります。
アイテムの説明も同じ理由で、モノの性質ではなく**それを使って何をするか**を書いています。

クイズの**正解と解説はサーバー側にのみ置き、配信される JavaScript には含めていません**。
採点は回答 API で行います（[docs/api.md](docs/api.md)）。

### キャラクターの見た目を確認する

髪型10種・服10種・装備10種の全パターンを並べた確認ページがあります。**サーバー不要**で、ビルド後に
`apps/web/public/avatar-preview.html` をブラウザで直接開くだけです。

```bash
pnpm build:web
# → apps/web/public/avatar-preview.html を開く
```

アプリ本体と同じ描画コード（`apps/web/src/avatar/sprite.ts`）を使っているので、
ここで見たとおりの姿が地図上にも出ます。描き直したら `pnpm build:web` で再生成してください。

### スマートフォンでの表示

狭い画面（900px 以下）では、**地図を全面に敷き、パネルはボトムシート**として下から引き上げます。
以前は上下 52%/48% で分けていたため地図が画面の半分しか使えませんでしたが、
たたんだ状態ではハンドルの 52px しか占有しません。

スポットを選ぶ・クイズが出る・キャラメイクを開くと、シートは自動で開きます。

### 歩いたエリアの開放

歩いた場所は霧が晴れます。晴れ方は 2 段階です。

| 単位 | 晴れ方 |
| :--- | :--- |
| タイル（50m 四方） | 通った場所を中心に半径 40m ぶん |
| **区画（300m 四方 ＝ 6×6 タイル）** | **その 25%（9 タイル）を歩くと全面が開く** |

区画の開放が無いと、300m 四方を全部晴らすのに道という道を歩く必要があり、現実的な散歩では
白い部分が延々と残ります。閾値は `EXPLORE_BLOCK_TILES` と `EXPLORE_UNLOCK_RATIO` で変えられます。

**霧はサーバーの応答を待たずに晴れます。** 送信は 30 秒ごとにまとめていますが、判定式は
サーバーと同じもの（`@map-checkin/core`）をクライアントでも呼んでいるため、
歩いた瞬間に反映され、あとから届く応答と食い違いません。

> **区画の決め方は `areaKeyOf`（`packages/core/src/exploration.ts`）に閉じ込めてあります。**
> いまはタイルを格子状に束ねていますが、本来は**町丁目の境界**を区画にしたいところです。
> 町丁目のポリゴンを用意できたら、この関数を「座標 → 町丁目コード」へ差し替えるだけで、
> 開放の判定も面積の集計もそのまま動きます（呼び出し側は区画キーの中身を見ていません）。

### バックエンドへのリクエストを抑える設計

**位置が変わってもサーバーには問い合わせません。** 表示に必要な情報のうち位置に依存するのは
距離と並び順だけで、これはクライアントで計算できるためです（`apps/web/src/spots.ts`）。
サーバーの `GET /v1/spots` は位置で絞り込みをせずエリア内の全件を返すので、
位置を渡さなくても顔ぶれは変わりません。

| きっかけ | リクエスト |
| :--- | :--- |
| 起動時 | client-config / spots / me / items / exploration の 5 本 |
| **定期同期（30秒ごと）** | spots / me / items の 3 本。他のユーザーのチェックインで倍率が変わる分を拾う |
| **歩いた記録（30秒ごと）** | exploration 1 本。同じタイルは積まないので、待つほど 1 本にまとまるだけ |
| 自分の操作 | チェックイン・クイズ回答・装備変更などの直後に、待たずに取り直す |
| 移動 | **なし** |

定常状態はおおよそ **6〜8 リクエスト/分**で、レート制限（既定 60 req/分）に対して十分な余裕があります。
タブが裏に回っている間は定期同期を止め、ページを離れるときは溜めている歩行記録を送り出します。

### 位置情報が無い環境でのデバッグ移動

位置情報が拒否・利用不可の場合（PC のブラウザなど）、地図の左下に**仮想ジョイスティック**が出ます。
倒している間ずっと現在地が動くので、チェックイン半径やクイズの導線を実際に歩かずに確認できます。

- 最大まで倒したときの速さは 32m/秒（約115km/h）。サンプルエリアの端から端まで1分弱で動けます
- 握っている間は `/spots` などを取り直しません。動きが止まってから 600ms 後に 1 回だけ更新します
- 現在地が無い状態では、対象エリアの中心から動き出します
- 位置情報が有効なときは表示しません（本番の機能ではありません）

## 試作中の機能

`?retro=1` を付けると、**まだ歩いていないエリアだけ**を 8bit 風のドット絵で表示します（[docs/retro-map-spike.md](docs/retro-map-spike.md)）。
歩いた場所は素の解像度に変わるので、探索が進むほど世界の解像度が上がっていきます。
粗さは `&retroWidth=160`、地名を消すなら `&retroLabels=0`、未踏エリアを市松模様にするなら `&retroFog=dither` です。
本採用するかは未定で、既定の表示には影響しません。

## 注意

- **認証はありません。** ユーザー識別はブラウザが生成した UUID をヘッダで送るだけで、他人を騙れます。
  公開環境に置かないでください（本番は LIFF ID トークンをサーバー側で検証します）。
- **スポットはデモ用の架空データです。** 実在の避難所指定や設備状況を表すものではありません。
  本番は FR-10-1 のオープンデータに置き換えます。
- **データストアはローカルで代替できません**（実行環境が接続情報を注入するため）。
  ローカル開発とテストはインメモリ実装（`packages/datastore/src/fake.ts`）で通します。
- チェックイン半径・クールダウン・ポイント配分は**暫定値**です（Issue #7 で確定）。
- 探索エリアは **50m 単位のタイルへ丸めて**保存します。生の GPS 軌跡は保存しません
  （「いつどこにいたか」の精度を必要以上に持たないため）。本番で行動履歴を扱う場合は、
  保存期間・削除導線・同意取得を別途設計してください。
