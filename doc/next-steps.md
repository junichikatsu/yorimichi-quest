## 1. 審査結果を待つあいだ（〜結果発表）

### やってよいこと

| 作業 | 理由 |
| :--- | :--- |
| ドキュメント・ビルド時ツール | 配信物に影響しない |
| ダッシュボード（`/dashboard.html`） | アプリ画面と別ファイル。提出物で「仮公開」と断ってある |
| サーバー側の追加（新ルート・新データ） | 既定で無効なら挙動が変わらない |
| **防災士ヒアリングとナレッジのレビュー** | 人に会う工程。コードに触れない |

### 避けること

**アプリ画面（`apps/web/src/`）を変えない。** 提出したスクリーンショットと動画が
固定されており、審査員が開いたときに食い違うと説明できない。

具体的には FR-05（写真投稿）・FR-06（相互検証）・FR-03-4（称号）が該当する。
この3つは**結果が出てから最優先で着手する**（下の 4 を参照）。

### 再デプロイの要否

**要らない。** `ENABLE_AI_QUIZ` が未設定なので、ナレッジもハザードも1件も参照
されない。デプロイしても**使わないデータを本番へ運ぶだけ**である。

デプロイするのは「承認済みナレッジがある」かつ「AI出題を有効にする」と決めたとき。

## 2. 防災士ヒアリング（9月）

**ヒアリングとナレッジのレビューは対象者が同じである。** 別々に頼まず、一度で済ませる。

### 2-1. フォームを立てる

1. [hearing-bousaishi-form.gs](hearing-bousaishi-form.gs) を https://script.google.com/ に貼る
2. `createHearingForm` を実行する（初回は Drive / Forms への承認を求められる）
3. 実行ログに出る「回答URL」を配る

設計は [hearing-bousaishi.md](hearing-bousaishi.md)。目標は**5名以上**（要件定義書 5.1 の
PSF 検証条件と同じライン）。

### 2-2. 同じ場でナレッジのレビューを頼む

[knowledge-review.md](knowledge-review.md) を印刷して渡す。**PR の diff（JSON）を
読ませない。** 32件、1件あたり数分で読める形にしてある。

見てほしいのは3点。

1. **正しいこと**が正しいか
2. **よくある誤解**が、本当に誤解か（＝事実に近いものが混ざっていないか）
3. **なぜ大切か**が、命に関わる理由として妥当か

> **2 がいちばん間違えやすい。** 事実に近い内容を「誤解」として出すと、逆のことを
> 教えてしまう。すでに1件見つかっている（`gen-aed-3` の「屋外設置のAEDは雨や気温の
> 影響で作動しないことがある」）。これは差し替え済みだが、**差し替えた文言自体は
> まだ確認を受けていない。**

### 2-3. あわせて確認したいこと

| 確認事項 | なぜ |
| :--- | :--- |
| **アンケートの12問が現地で答えられるか** | 設問は固定で、`fieldKey` がそのままCSVの列になる。歩いてみないと分からない（[#14](https://github.com/junichikatsu/yorimichi-quest/issues/14)） |
| **スフィア基準の項目を訓練で取れるか** | 便器数・男女別・夜間照明は避難所の内部情報で、平時に一般市民は入れない。**避難所運営訓練で内部に入る人だけが取れる** |
| ナレッジの**一次資料** | いまの出典は「生成・未レビュー」のまま。JRC蘇生ガイドライン、内閣府の避難所運営ガイドラインなどへ紐づけたい |

## 3. レビュー後の作業

### 3-1. 直すものがある場合

**生成物（`knowledge-base.ts`）を手で編集しない。** 次の再生成で消える。

`tools/kb/overrides.json` に書く。

```json
{
  "gen-aed-3": {
    "reason": "なぜ直したかを必ず書く（次に読む人の手がかり）",
    "distractors": ["差し替えた選択肢1", "差し替えた選択肢2"]
  }
}
```

差し替えられるのは `claim` / `context` / `distractors` / `why` / `kind` / `sources`。

### 3-2. 承認する

`tools/kb/approved.json` の該当 `entryId` の `approved` を `true` にする。

### 3-3. 反映して確認する

```bash
pnpm build:kb          # モデルを呼ばない。鍵は要らない
```

出力に承認件数が出る。`doc/knowledge-review.md` も同時に更新される。

> **直したものは承認が自動で外れる。** 指紋が変わるためで、**自分の直しを自分で
> 承認して素通しすることはできない。** 直したら、もう一度読んでもらう。

### 3-4. 検証する

```bash
pnpm verify            # typecheck → lint → test → ZIP
```

### 3-5. AI出題を有効にする

enebular 実行環境の envVars に2つ入れる。

```
ENABLE_AI_QUIZ=true
ORCAROUTER_API_KEY=<鍵>
```

**片方だけでも安全側に倒れる。**

| 状態 | 挙動 |
| :--- | :--- |
| 両方なし | 固定データの12問（いまの本番） |
| 鍵のみ | 固定データのまま（`ENABLE_AI_QUIZ` が二重の鍵） |
| フラグのみ | **ナレッジから出題**されるが、言い回しは素のまま。出題は成立する |
| 両方 | ナレッジから出題し、軽量モデルが言い回しを整える |

その他（`ORCAROUTER_BASE_URL` / `AI_RUNTIME_MODEL` / `AI_QUIZ_TIMEOUT_MS`）は
既定値があるので**設定不要**。

### 3-6. デプロイする

```bash
gh workflow run imanouchi-deploy.yml --ref <ブランチ> -f environment=production
```

デプロイ後に自動でスモークテストが走り、`/v1/health` の `commit` が一致するかを見る。

### 3-7. 動作を確かめる

```bash
curl -s https://lcdp002.enebular.com/imanouchi/v1/health
```

`configOk: true` を確認する。そのうえで LINE ミニアプリでスポットのクイズを開き、
**出題が変わっていること**を見る。ログに `[quiz] ナレッジ N 件から出題します` が出る。

戻したくなったら **`ENABLE_AI_QUIZ` を消すだけ**でよい（デプロイ不要）。

## 4. 審査結果が出たら

### 通過した場合

Final Stage は 9月〜10月。**アプリ画面の制約が外れる**ので、順序はこうなる。

| 順 | 作業 | なぜこの順か |
| ---: | :--- | :--- |
| 1 | **FR-05（写真投稿）・FR-06（相互検証）** | これが無いと**スポット層のナレッジが作れず**、ダッシュボードのスフィア基準も想定値のまま。他のすべてが待っている |
| 2 | ナレッジのスポット層 | 1 で市民の回答が入って初めて材料ができる |
| 3 | FR-03-4（称号）・残りのゲーム要素 | 画面が変わるもの。1・2 の後で足りる |
| 4 | 実証実験フェーズ（11月〜2月） | タイムラインどおり |

### Final Stage で使える手札

**First Stage で1つも使っていない材料が残っている**（[pitch-first-stage.md](submission-final/pitch-first-stage.md) 末尾）。

| 材料 | 状態 |
| :--- | :--- |
| **実データ370件のうち232件が属性の空欄** | ダッシュボードで**画面になった**（1,110スロット中1,005が空白） |
| **CSVで行政へ返せる** | **実装済み。実際に落とせる**（未取得項目の一覧が1,110行） |
| **町丁目という行政の単位で返す** | 実装済み（123町丁目・CSV出力あり） |
| **歩きスマホを招かない設計** | 実装済み。実測で iOS/Android 両方で音が鳴る |
| **AIを役割で二段に分ける** | **型で保証した**（実行時から高性能モデルへ手が届かない） |
| **人が確かめたナレッジしか配らない** | 承認台帳で執行。未承認は配られない |
| 有事モードを訓練日に立てれば実地の避難訓練になる | 未実装。「なります／目指します」で言う |

### 通過しなかった場合

上の 4 の順序はそのまま使える。締切が外れるだけで、作るものは変わらない。
**9月の現場検証フェーズは発表済みの約束なので実施する。**
