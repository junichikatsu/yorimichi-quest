## 1. 記述欄（310字制限のある5欄）

数値はすべて [都民ヒアリング（n=37）](hearing-citizens.md)の実測値である。**推計や引用ではなく自分たちが取った数字**なので、審査で根拠を問われても答えられる。

### 2-3 サービスの詳細（265字／310字）

> 街を歩いて防災データを集める位置情報ゲームです。現在地の地図に避難所・AED・バリアフリートイレ・給水スポットが並び、近づくとチェックインできます。その場で出る問題は「大きな地震の直後に何をするか」など行動を問い、正解すると内容がカードとして手元に残ります。カードは行動・道具・場所・ミッションの4種で、状態は達成と未達成だけです。未達成でも枠と達成条件は見えているため、何が残っているかが常に分かります。歩いた範囲は地図の霧が晴れて記録されます。投稿写真はAIが属性を読み取り、他の利用者による現地確認を経て検証済みになります。

### 2-4 着目した課題・背景（271字／310字）

> 防災アプリは有事にしか開かれず、平時の学習が進みません。都民37名への調査では、最寄りの避難所の場所が浮かぶ人は67.6%いる一方、水害対応やトイレ設備といった場所以外の情報を知る人は16.2%でした。場所を知る人の約76%は名前しか知りません。通信障害時に避難所やルートが浮かばない人は40.5%です。さらにベビーカーや車椅子で移動する人では、10人中6人が段差や設備の不備で遠回りを経験し、非該当者では1件も起きていません。行ける場所が人によって違うのに、その差を埋める情報が現地にしかない。自治体HPを防災目的で見た人は5.4%でした。

**67.6% と 16.2% の対比がこのサービスの存在理由そのもの**である。資料でも1枚のグラフにする。

### 2-5 課題・背景の解決方法（283字／310字）

> 平時に開かれないなら、平時の行動に乗せます。調査では週2回以上街を歩く人が91.9%、街で写真を撮る人が75.7%いました。すでにある移動にゲームを重ねるので、新しい習慣を作らせません。学習は座学ではなく、その場所に立って行います。避難所の前で中身を問われるため、名前しか知らない状態から先へ進みます。副産物として、行政が持たない現地の属性（段差、オストメイト対応、夜間の使用可否）が集まり、相互検証を経て自治体へ返ります。成果は行ける場所が増えることです。遠回りは日常の時間を削り、有事には探す時間が命を削ります。平時に歩いて覚えた分だけ、その両方が短くなります。

**★ 末尾3文がソーシャルインパクトの受け皿である。** 明示欄が無いためここで受ける。

以前の草案は「『手取り時間が増える』型の効果ではない」として**自分から降りていた**。降りる必要はない。手元のヒアリングに時間の話が2つある。

| 実測値 | 時間の損失 |
| :--- | :--- |
| ベビーカー・車椅子利用者の**10人中6人**が段差で遠回りを経験 | 日常の時間 |
| 通信障害時に避難所やルートが浮かばない人が **40.5%** | 災害直後に「探す」時間 |

基準文の例示が「手取り時間の増加等」であるため、**同じ語で受ける**。

### 3-1 技術選定の理由（285字／310字）

> enebularのクラウド実行環境とデータストアで完結させ、静的配信も同一オリジンで行います。データストアはKVSでJOIN・二次索引・地理検索・集計を持たないため、設計で吸収しました。スポットはエリア単位でパーティションを切り、距離計算はアプリ側で行います。集計関数がないので、行動記録と同時に日次カウンタを加算します。地図はMapbox GL JSで、未到達領域の霧をキャンバスで重ねています。フロントはReactとTypeScriptをesbuildで単一ファイルに束ね、配信を1リクエストに収めました。移動中の再取得は距離計算をクライアントへ移して止めています。

**「選んだ理由」ではなく「制約をどう設計で吸収したか」を書いている。** 技術力の基準は合理性を見るため、KVSに地理検索がないという不利な事実を先に置き、その対処を並べる構成にした。

**この欄はすべて実装済みである**（同一オリジン配信・パーティション設計・霧のキャンバス・esbuild の単一ファイル・クライアント側の距離計算）。日次カウンタ（FR-11）だけが未実装なので、「加算します」は設計の記述として読ませる。

### 3-2 生成AI等の活用方法（301字／310字・任意欄）

> AI処理はDify Cloud上のアプリとして構成し、モデルはGeminiを選定しました。高性能モデルと軽量モデルを役割で分けます。高性能モデルはオープンデータの取り込み時に一度だけ使い、表記ゆれ・欠損・自由記述を、出典と取得日を保った構造化ナレッジへ整えます。写真からの属性抽出と個人情報の判定もここに寄せます。軽量モデルは利用時に都度使い、整ったナレッジだけを材料に現地の問題と解説を作ります。入力が整っているため軽量でも品質が出て、コストが利用者数に比例しません。防災の文言の誤りは命に関わるため、都度生成に自由な知識を持たせず、検証済みの範囲でしか書かせません。問題の正解は配信物に含めません。

任意欄だが**技術力の受け皿なので必ず埋める**。

**★ 芯は「モデルを役割で分ける」ことである（#75）。** 高性能モデルは**取り込み時に一度だけ**、軽量モデルは**利用時に都度**。これが効く理由は3つある。

| 論点 | 主張 |
| :--- | :--- |
| コスト構造 | 高性能モデルの呼び出しは**データ件数に比例**（実データ370件・増分のみ再実行）、軽量モデルの呼び出しは利用者数に比例する。**「利用者が増えるほど高性能モデルを叩く」形を避けている**ので、助成金が切れても続けられる（1-9 の自走可能なエコシステムと繋がる） |
| 品質 | 軽量モデルが弱いのは「散らばった情報から意味を組み立てる」作業で、それは取り込み時に済んでいる。整った入力から文を作るだけなら軽量で足りる |
| **安全** | 防災の文言の誤りは命に関わる。**都度生成に自由な知識を持たせない**ことで、誤りの範囲を「人が検収した一度ぶんのナレッジ」の中に閉じ込められる。「生成AIを防災に使って大丈夫か」への回答を、注意書きではなく**構造**で示せる |

**★ 後付けの説明ではない。** 二段構えは既にその形に作ってある。

- `tools/ingest/ingest.mjs` — **ネットワークへ出るのはこのスクリプトだけ**で、再実行可能、出典と取得日をスポットごとに保持する。高性能モデルを差し込む先がバッチであることが既に前提になっている
- `apps/function/src/data/spot-dataset.ts` — 配信側は生成済みファイルを読むだけ（外部へ取りに行かない）。「整ったナレッジ」の置き場
- `QuizPrompt.generatedBy: 'fixture' | 'llm'` — **どちらで出したかを記録する欄が実装済み**。生成が落ちて固定データに落ちたことを隠さないため

**★ 時制を「設計」に寄せてある。** AI は未実装であり、選定とAPIキーの確保が #5 で未決である。以前の草案は「作り」「Geminiです」と断定していたが、First Stage で動かせないものを断定すると完成度の主張と衝突する。**「構成し」「選定しました」「分けます」なら事実に反しない。**

**★ 字数で落とした点。** 「プロンプト・モデル選択・入出力スキーマをDify側に置き、改訂にデプロイを要しない」という運用の利点は良い材料だが、二段構えと両方は 310 字に入らない（330字になる）。**二段構えのほうが技術力（合理性）に効く**ため、そちらを採った。落とした点はプレゼンの口頭で足せる。

末尾の1文（配信物に答えを載せない）は実装上の判断で、**テストで固定してある**。未達成カードの中身を応答から落とす件も同様（FR-14-3）。

### カットの順序について

**3→6' が主張の背骨である。** 平時に歩いて記録が増える（3）ものが、有事に切り替えると使える形で出てくる（6'）。この2つが繋がって見えないと、位置情報ゲームが防災に効く理由が伝わらない。

**5' を入れる理由は、安全設計が実装されていることを示すためである。** 「歩きスマホを助長するのでは」という疑問は必ず出る。先に答えておく。

**7' は実現可能性への回答である。** 審査員が自分の端末で触れることを、画面で示す。

### 撮影上の制約

| 制約 | 内容 |
| :--- | :--- |
| **Mapbox の帰属表示** | ロゴと帰属を**隠さない・改変しない**。**キャプチャと埋め込み動画に写っている必要がある**（提出資料にも及ぶ） |
| **BGM を入れない** | 権利の確認ができないため。静かな場所で録る |
| **デバッグ用ジョイスティックを映さない** | 位置情報が有効なら表示されない。**屋外の実機で撮る。**ジョイスティックでの移動を「歩いている」として見せてはいけない |
| **カット5' は実機で歩いて撮る** | 模擬位置では歩行中モードが作動しない（デモの最中に画面が覆われるのを防ぐため、意図的にそうしてある） |
| **カット6' の赤いバナー** | 「デモ表示であり実際の災害情報ではありません」は**消さない**。実装でも消せないようにしてある |
| **画面キャプチャ** | 1600×900px・1〜3枚。**カット2（地図）・カット6'（有事モード）・カット4（属性の空欄）**が候補 |
