## 方針

**12枚を全部説明しない。** 2分で12枚だと1枚10秒、どの主張も刺さらない。**8枚で話し、4枚は黙って通す**（下表）。

**提出フォームに書いたことを読み上げない。** 審査員は 2-3〜2-5・3-1・3-2 を読んでいる。**口頭は「資料に入らなかったこと」に使う。** 具体的には次の3つを声で入れる。

| 声で入れるもの | なぜフォームに無い／弱いか |
| :--- | :--- |
| **実データ370件のうち232件が属性の空欄** | フォームは「ミクロデータが不足」と書いただけ。**自分たちのデータで数を言える**のはここだけで、いちばん強い |
| **歩きスマホを招かない設計**（歩き出すと画面を伏せ、音で知らせる） | 2-3 に一文あるだけで、**資料の12枚には1枚も無い**。「位置ゲームで歩かせて大丈夫か」は必ず出る疑問なので先に潰す |
| **町丁目という行政の単位で返す**（e-Stat 小地域境界256区画） | 4-1 にデータ名が並ぶだけで、**なぜ使ったかが提出物のどこにも無い** |

**締めは「将来的に防災訓練ができる」に置く。** スライド4に既に「いつもの散歩を防災訓練に変える」とあるので、資料と衝突しない。**有事モードは管理者の操作で立てられる**ので、これを自治体の訓練日に立てれば実地の避難訓練になる——という筋で話す。**「できます」ではなく「なります／目指します」**で言う（訓練モードは未実装）。

## 聞かれたら足す材料（原稿には入れていない）

Final Stage や質疑で使う。**どれも根拠が手元にある。**

| 材料 | 中身 |
| :--- | :--- |
| 取り込みコスト | 取り込みは待てる処理なので**非同期のバッチ実行（同期の半額）**に置ける。高性能モデルの呼び出しは**増分のみ** |
| クイズの安全 | **配信するJavaScriptに正解を載せていない**（テストで固定済み） |
| 入口の低さ | **LINEログインなしで地図と有事モードに触れる**。おためしの記録は端末内だけに置き、サーバーへ送らない |
| 区ごとの欠落 | **千代田区にAEDのデータが無く、港区に公衆トイレのデータが無い**。4カテゴリを揃えるには両区が必要だった＝公開データの欠落そのもの |
| 行政の単位 | 探索の区画を格子ではなく**町丁目（e-Stat 小地域境界256区画）**にしてあるので、記録件数を人口と並べられる |
| 避難所の国際基準 | 便器数・男女別・夜間照明は**スフィア基準の充足率**に変換して返す。ただしこれらは避難所の内部情報で、**平時に一般市民は立ち入れない**。だから**避難所運営訓練で内部に入る防災士・消防団員が担う**（訓練とデータ収集が繋がる根拠） |
| 端末機能の実測 | 進捗の通知音は**iOS・Android両方で鳴る**。振動はAndroidのみ、画面の常時点灯は両方で成功。**歩きスマホ対策が実測で成り立っている** |
