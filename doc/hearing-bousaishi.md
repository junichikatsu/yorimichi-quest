# 防災士ヒアリング アンケート設計（#14 データ辞書の入力）

| 項目 | 内容 |
| :--- | :--- |
| 目的 | Issue #14「収集する防災データ項目の定義（データ辞書 / FR-12-1）」を決めるための一次情報を、防災士・消防団員から集める |
| 対象 | 防災士、消防団員、自主防災組織・自治体防災担当・要配慮者支援団体（#10 で初期ターゲットに設定した層） |
| 目標回答数 | 5名以上（要件定義書 5.1 の PSF 検証条件と同じライン） |
| 形式 | Google フォーム（無記名・全問任意）。所要 10〜15分 |
| フォーム生成 | [hearing-bousaishi-form.gs](hearing-bousaishi-form.gs) を Apps Script に貼って実行する |
| 期限 | #14 の一次確定が 8/22 のため、それに間に合う回収期限を設定する |

## このアンケートで何を確定させるか

#14 の「決めること」との対応。設問はすべてこの表の左列に紐づけている。

| #14 の決定事項 | 対応する設問 |
| :--- | :--- |
| スポットカテゴリごとの収集項目リスト | S3〜S6 の重要度グリッド（避難所／バリアフリートイレ／AED／給水スポット）＋各カテゴリの「他に必要な項目」自由記述 |
| 各項目のデータ型と選択肢の定義 | S7「段差の高さは選択肢で足りるか」など粒度の設問 |
| AIが写真から抽出する／ユーザーが手入力する の切り分け | S3〜S5 の「写真1枚＋タップ数回で答えられそうな項目」チェックボックス、S7「写真では分からない項目」自由記述 |
| 取込済みオープンデータとの突合・既存項目の除外 | S2「公開データが実態と違った経験」＋具体例。重要度グリッドの選択肢に「既存データで分かる」を用意して除外候補を拾う |
| MVPデモで使う項目の絞り込み | S8「まずこれだけ集まれば価値がある項目 上位3つ」 |
| 担当者と期限 | アンケート対象外（プロジェクト側で決める） |

## 設計上の判断

- **「記録に残していないが自分は知っている情報」を聞く設問（S2 最後）を核に置いた。** #14 の狙いは行政データの穴を埋めることなので、既存項目の確認より、暗黙知の言語化のほうが価値が高い。
- **重要度グリッドの3列目を「不要／既存データで分かる」にした。** 除外判断（FR-12 の定義原則の第1項）を回答者側から拾うため。
- **写真で答えられるかを、カテゴリごとに回答者に選ばせる。** FR-05-2（Dify AI-1）の抽出対象を決める入力になる。避難所・トイレ・AED の3カテゴリのみに置き、給水・共通では省いて設問数を抑えた。
- **「一般ユーザーに集めさせるのが不安な項目」を聞いている（S8）。** 誤情報が避難行動を誤らせる項目は、相互検証（FR-06）の必須対象にするか、そもそも収集項目から外す判断が必要になる。
- **全問任意・無記名。** 連絡先は追加ヒアリング希望者のみの任意入力にし、目的をフォーム冒頭に明記している。

## 運用メモ

- 配布時は「担当エリアの実情を教えてほしい」という依頼文を添える。項目リストの正解合わせではなく、暗黙知の収集が目的だと先に伝えると自由記述の質が上がる。
- 自由記述（S2 最後、各カテゴリの追加項目、S7）が実質の本体。集計時はここを先に読み、グリッドの数値は優先順位づけに使う。
- 回答が集まったら、#14 に「カテゴリ×項目×データ型×取得手段（AI／手入力）」の表として起票する。
- 追加ヒアリング希望者には 30分の個別ヒアリングを設定し、S7・S8 の回答を起点に深掘りする。
