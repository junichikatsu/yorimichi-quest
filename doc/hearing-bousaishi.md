| 項目 | 内容 |
| :--- | :--- |
| 目的 | Issue #14「収集する防災データ項目の定義（データ辞書 / FR-12-1）」を決めるための一次情報を、防災士・消防団員から集める |
| 対象 | 防災士、消防団員、自主防災組織・自治体防災担当・要配慮者支援団体（#10 で初期ターゲットに設定した層） |

## このアンケートで何を確定させるか

#14 の「決めること」との対応。設問はすべてこの表の左列に紐づけている。

| #14 の決定事項 | 対応する設問 |
| :--- | :--- |
| スポットカテゴリごとの収集項目リスト | S3〜S6 の重要度グリッド（避難所／バリアフリートイレ／AED／給水スポット）＋各カテゴリの「他に必要な項目」自由記述 |
| 各項目のデータ型と選択肢の定義 | S7「段差の高さは選択肢で足りるか」など粒度の設問 |
| AIが写真から抽出する／ユーザーが手入力する の切り分け | S3〜S5 の「写真1枚＋タップ数回で答えられそうな項目」チェックボックス、S7「写真では分からない項目」自由記述 |
| 取込済みオープンデータとの突合・既存項目の除外 | S2「公開データが実態と違った経験」＋具体例。重要度グリッドの選択肢に「既存データで分かる」を用意して除外候補を拾う |
| MVPデモで使う項目の絞り込み | S8「まずこれだけ集まれば価値がある項目 上位3つ」 |
| 担当者と期限 | アンケート対象外（プロジェクト側で決める） |

## 避難所の構造的課題に関する調査を受けた追補

熊本地震・能登半島地震の検証（災害関連死、スフィア基準、TKB＝トイレ・キッチン・ベッド問題）を踏まえ、S3 と S8 に設問を追加した。

### S3 に追加した項目

| 追加項目 | 根拠 |
| :--- | :--- |
| **トイレの便器の数（男女別の内訳）** | スフィア基準は「避難者20人に1基」「男女比1:3」を示す。**基数が分かればダッシュボードで充足率を計算できる**（要件定義書 FR-09-6・9.1）。従来の「トイレの数・様式・車いす対応」を数と様式に分割した |
| **断水したときにトイレが使えるか（仮設・マンホールトイレの備え）** | 能登半島地震では断水でトイレが使えず、屋外へ向かった高齢者が転倒・低体温症で死亡した事例が報告されている |
| **要配慮者用のスペースの有無（福祉避難所に指定されているか）** | 個別避難計画の作成率が全国で15.1%にとどまり、要配慮者の避難先が平時に決まっていない |
| **段ボールベッドなど、床に直接寝ないための備え** | TKB の B。床からの高さ30〜40cmを確保すると、ホコリの吸入（誤嚥性肺炎の一因）と冷えを抑えられる |
| 電源の項目に「停電時に冷暖房が使えるか」を追記 | 能登では暖房が使えず高齢者が急性心不全・肺炎で死亡する事例が多発した |

> **設問文には基準の数値や災害事例を書いていない。** 「20人に1基が国際基準」と説明すると回答が誘導され、現場の実感ではなく基準の復唱になるため。項目を並べるだけに留め、重要度の判断は回答者に委ねている。

### 「建物の中に入らないと分からない項目」を切り分ける設問を追加した

S3 に「このうち、建物の中に入らないと確認できない項目」、S8 に「担当エリアの避難所の建物の中を見られる機会」と「中の情報をどう集めるのが現実的か」を追加した。

**これは #14 の中で最も設計を左右する情報である。** 上に挙げたトイレの基数・要配慮者スペース・ベッドの備えは、いずれも**避難所の内部情報**であり、指定避難所の多くは学校施設のため**平時に一般市民は立ち入れない**。この切り分けをせずに項目リストを確定すると、**一般ユーザーに原理的に答えられない質問を出すアプリ**になる。

したがってデータ辞書は次の2群に分けて定義する必要がある。

| 群 | 取得者 | 例 |
| :--- | :--- | :--- |
| **平時に外から観測できる** | フェーズ2（一般層）も可 | 入口の段差・スロープ、外部トイレ、周辺の道、夜間の照明、AED、給水スポット |
| **中に入れる機会でないと取得できない** | **フェーズ1（防災士・消防団員）に限定** | トイレの便器数、要配慮者スペース、備蓄品の置き場所、経路の段差 |

この制約は、初期ターゲットを防災コミット層に置いた判断（要件定義書 4.1）の4つ目の根拠にもなっている。**一般市民には物理的に取得できないデータを取れる唯一の層である**という点で、フェーズ1がフェーズ2の「お手本データ」を作る構造が裏づけられる。

## 設計上の判断

- **「記録に残していないが自分は知っている情報」を聞く設問（S2 最後）を核に置いた。** #14 の狙いは行政データの穴を埋めることなので、既存項目の確認より、暗黙知の言語化のほうが価値が高い。
- **重要度グリッドの3列目を「不要／既存データで分かる」にした。** 除外判断（FR-12 の定義原則の第1項）を回答者側から拾うため。
- **写真で答えられるかを、カテゴリごとに回答者に選ばせる。** FR-05-2（Dify AI-1）の抽出対象を決める入力になる。避難所・トイレ・AED の3カテゴリのみに置き、給水・共通では省いて設問数を抑えた。
- **「一般ユーザーに集めさせるのが不安な項目」を聞いている（S8）。** 誤情報が避難行動を誤らせる項目は、相互検証（FR-06）の必須対象にするか、そもそも収集項目から外す判断が必要になる。
- **全問任意・無記名。** 連絡先は追加ヒアリング希望者のみの任意入力にし、目的をフォーム冒頭に明記している。
- **設問追加により S3 の重要度グリッドが12行から16行に増えた。** 所要時間は 10〜15分の想定を維持できる見込みだが、回収状況を見て負担が大きいようなら S3 の一部を「その他」の自由記述へ寄せる。

## 運用メモ

- 配布時は「担当エリアの実情を教えてほしい」という依頼文を添える。項目リストの正解合わせではなく、暗黙知の収集が目的だと先に伝えると自由記述の質が上がる。
- 自由記述（S2 最後、各カテゴリの追加項目、S7）が実質の本体。集計時はここを先に読み、グリッドの数値は優先順位づけに使う。
- 回答が集まったら、#14 に「カテゴリ×項目×データ型×取得手段（AI／手入力）×**取得可能な層（フェーズ1限定／一般も可）**」の表として起票する。
- 追加ヒアリング希望者には 30分の個別ヒアリングを設定し、S7・S8 の回答を起点に深掘りする。
